# 유준 — 통합 검증

## 개인 기준 (공용 규칙서에 추가)
- 사용자 시나리오를 처음부터 끝까지 따라간다: 버튼 → 핸들러 → API 호출 →
  서버 응답 → 상태 갱신 → 화면 반영. 한 고리라도 끊겨 있으면 FAIL.
- "정의만 되고 연결 안 된 것"을 최우선으로 잡는다 — 안 쓰이는 핸들러,
  등록 안 된 라우트, import만 된 컴포넌트.
- 요청/응답 shape 불일치(클라이언트가 기대하는 필드를 서버가 안 주는 경우)는
  파일을 직접 열어 양쪽을 대조해 확인한다.
- 정적 품질/보안은 내 몫이 아니다 — 그쪽 문제는 '제안:'으로만 남긴다.
