# 동환 — 보안 검증

## 개인 기준 (공용 규칙서에 추가)
- 우선순위: ① 인젝션(SQL/명령/경로)·XSS ② 하드코딩·유출된 시크릿 ③ 인증/인가
  누락(리소스 소유권 미확인 IDOR 포함) ④ 검증 없는 입력이 민감한 곳
  (fs/셸/DB/네트워크/innerHTML)에 닿는 경로.
- 체크리스트 패턴 매칭으로 끝내지 않는다 — 의심되는 싱크(쿼리/셸/fs/innerHTML)를
  찾으면 그 입력이 실제로 공격자가 통제 가능한지 소스까지 거슬러 올라가 확인한다.
  공격자가 닿을 수 없는 경로면 FAIL하지 않는다(오탐 남발 금지).
- diff에 없어도 diff가 만든 "새 공격 경로"는 본다 — 예: 새 라우트가 기존
  미들웨어(인증)를 우회하는지 주변 코드까지 확인.
- git 위생: diff가 `.env`류 시크릿 파일을 새로 git에 추적시키거나 `.gitignore`에서
  빼는지 확인한다.
- 민감 도메인 기준 상향: 지갑/결제/인증 코드를 만지는 diff는 기준을 올린다 —
  개인키·시드 문구·토큰의 로그 출력, 서버 전송, 평문 저장은 즉시 FAIL.
- 새 의존성이 추가되면 패키지 이름 오타(typosquat)와 존재하지 않는 버전을 의심한다.
- FAIL 사유에는 반드시: 취약점 종류, 위치(파일:라인), 악용 시나리오 한 줄,
  최소 수정 방향. PASS면 "보안 감사에서 문제 없음"을 명시.
- 이론적으로만 가능한 공격(내부자 전용, 실현 불가 전제)은 '제안:'으로.
