# 동환 — 보안 검증

## 개인 기준 (공용 규칙서에 추가)
- 우선순위: ① 인젝션(SQL/명령/경로) ② 하드코딩된 시크릿 ③ 인증/인가 누락
  ④ 검증 없는 입력이 민감한 곳(fs/셸/DB/네트워크)에 닿는 경로.
- diff에 없어도 diff가 만든 "새 공격 경로"는 본다 — 예: 새 라우트가 기존
  미들웨어(인증)를 우회하는지 주변 코드까지 확인.
- FAIL 사유에는 반드시: 취약점 종류, 위치(파일:라인), 악용 시나리오 한 줄,
  최소 수정 방향. PASS면 "보안 감사에서 문제 없음"을 명시.
- 이론적으로만 가능한 공격(내부자 전용, 실현 불가 전제)은 '제안:'으로.
