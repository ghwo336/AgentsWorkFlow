# 🏢 LoopWorks — 에이전트들의 회사

> 여러 역할의 AI 에이전트를 한 팀으로 고용해서, 기획부터 커밋까지 스스로 돌아가는
> **멀티 에이전트 개발 루프**. 사람은 팀 리더로서 기획을 함께 다듬고 계획을 승인하면,
> 나머지는 우리 사무실의 에이전트들이 알아서 합니다.

```
나(리더) ─ 기획 상의 ─▶ 📋 호재 (Opus)
                          │  계획 수립 · 단계 분해 · 팀 배치
                          ▼
                     ★ 내가 승인
                          │
        ┌── 단계 1 ──────┼──────────────────────────┐
        │                ▼                           │
        │   🔨 개발 (Sonnet) — 단계 담당 전문가       │
        │      태경(프론트) 민재(백엔드) 주희(iOS)    │
        │      성민(Android) 연한(RN)                │
        │                ▼                           │
        │   🔍 검증 팬아웃 — 전원 통과까지 반려       │
        │      주호(코드 품질, codex)                 │
        │      동환(보안, codex)                      │
        │      유준(통합/런타임, Claude)              │
        │      성호(빌드 실제 실행)                   │
        │         │ FAIL → 사유와 함께 개발자에게 ↩   │
        │         │        (재시도 → 호재 개입 →      │
        │         │         그래도 안 되면 리더 호출)  │
        │         ▼ ALL PASS                         │
        │   ✅ git 커밋                               │
        └── 다음 단계 반복 ── … ──▶ 🎉 목표 완수
```

## 핵심 규칙

- **검증을 전부 통과하기 전엔 다음 단계로 못 넘어간다.** 검증자가 거절하면 그 사유가
  그대로 개발자에게 돌아가 같은 단계를 다시 구현한다. 재시도가 쌓이면 리드(호재)가
  개입해 근본 원인을 진단하고, 그래도 막히면 사람(리더)에게 결정을 넘긴다.
- **단계마다 스택이 맞는 전문가가 배정된다.** 호재가 계획을 세우며 각 단계의 담당
  개발자(`프론트 단계 → 태경`, `API 단계 → 민재`)까지 정한다.
- **통과한 단계는 즉시 커밋.** run마다 격리된 git 저장소에서 단계 = 커밋 단위.

## 우리 팀

| | 이름 | 직책 | 엔진 | 하는 일 |
|---|---|---|---|---|
| 📋 | 호재 | 기획 리드 | Claude Opus | 요구사항 상의 → 계획·단계 분해 → 팀 배치 → 막힐 때 개입 |
| 🔨 | 태경 | 프론트엔드 | Claude Sonnet | 웹 UI/UX |
| 🔨 | 민재 | 백엔드 | Claude Sonnet | API/DB/인증 |
| 🔨 | 주희 | iOS | Claude Sonnet | Swift/SwiftUI |
| 🔨 | 성민 | Android | Claude Sonnet | Kotlin/Compose |
| 🔨 | 연한 | 크로스플랫폼 | Claude Sonnet | React Native/Expo |
| 🔍 | 주호 | 코드 품질 | codex | SOLID·DRY·계층 등 공학 원칙 심사 |
| 🔍 | 동환 | 보안 | codex | 인젝션·시크릿·인가 등 보안 감사 |
| 🔍 | 유준 | 통합 | Claude Sonnet | "실제로 돌아가나" — UI↔API 배선 추적 |
| 🔍 | 성호 | QA(빌드) | 로컬 실행 | 빌드/타입체크를 진짜로 돌려서 판정 |
| 📡 | 상현 | X 리서치 | Grok | X(트위터) 실시간 검색 — 동향·여론·계정 발표 추적 |
| 📚 | 예림 | 웹 리서치 | Claude Opus | X 밖 웹 전반 — 공식 문서·구글·레딧·기술 매체 종합 |

각 에이전트는 **자기만의 하네스**(전문 분야·작업 규칙 —
[`packages/orchestrator/agents-config/`](packages/orchestrator/agents-config/)의 md 파일)를
갖고 일합니다. 파일만 고치면 그 에이전트의 일하는 방식이 바뀝니다.

## 리서치 팀 — 대화형 조사 스레드

홈의 **🔍 리서치 탭**은 코드 파이프라인과 분리된 조사 전용 화면입니다.
질문 하나 = 탭 하나 = 대화 스레드 하나.

- 질문을 던지면 **상현(Grok)이 X를, 예림(Claude)이 웹을 동시에** 조사해서
  보고서 두 개가 나란히 스레드에 쌓입니다. X는 로그인월 안이라 Grok의
  실시간 X 검색(search_x)이 아니면 볼 수 없는 영역이에요.
- 보고서가 나온 뒤(상태 `reported`)에도 같은 탭에서 **후속 질문**을 계속 이어갈
  수 있습니다 — 이전 질문/보고서 전체가 맥락으로 전달됩니다.
- **폴더**로 리서치들을 주제별로 묶을 수 있습니다 (예: 📁 블록체인). 폴더를
  고른 채 새 리서치를 시작하면 그 폴더로 자동 분류되고, 스레드의 드롭다운으로
  언제든 옮길 수 있어요. 폴더를 지워도 안의 리서치는 미분류로 돌아갈 뿐
  지워지지 않습니다.

## 쓸수록 똑똑해지는 팀 — 학습 루프

run이 끝나면 회고가 그 run의 **검증 실패 이력**(거절 사유들)에서 다음에도 유효한
교훈을 추출합니다. 모든 교훈은 `[조건]`이 강제됩니다 — 무조건 규칙이 프로젝트를
넘나들며 충돌하는 것을 형식 수준에서 막기 위해서.

- **프로젝트 운영 사실** ("빌드 전 prisma generate 필요") →
  `agents-config/learned/projects/<프로젝트>.md`에 **자동 축적**, 그 프로젝트의
  모든 계획/빌드 프롬프트에 주입 (run마다 재로드 — 재시작 불필요).
- **팀원 행동/방법 교훈** → **제안함**에 올라가고, 팀 소개 탭에서 사용자가
  승인한 것만 그 팀원의 기억(`learned/agents/<id>.md`)에 편입됩니다 —
  계획 승인 게이트의 학습판. 틀린 교훈은 md 파일에서 그냥 지우면 됩니다.

## 쓰는 방법

1. **대시보드에서 프로젝트를 만들고**, 호재와 채팅으로 요구사항을 다듬는다.
2. 팀은 기본 **"🤖 호재가 배치"** — 프로젝트 성격에 맞는 개발자·검증자를 호재가 고른다.
   원하면 좌석을 직접 선택할 수도 있다 (검증만 뽑으면 **프로젝트 감사 모드**,
   기획 없이 개발만 뽑으면 승인 없이 바로 구현).
3. 계획이 오면 **승인/수정 요청/거절**. 승인하면 루프가 돌기 시작한다.
4. 진행도·팀 채팅·노드 그래프·타임라인으로 구경하다가, 팀이 막히면 호재와 상의해서
   지침을 주거나 커밋/건너뛰기/중단을 결정한다.
5. **Usage 탭**에서 모델별/에이전트별 토큰 사용량·비용을 확인한다.

## 실행

```bash
npm install
npm run db:push        # SQLite 스키마 반영
npm run dev            # orchestrator(:4000) + dashboard(:3737) 동시 실행
```

전제: Claude Agent SDK 인증(Claude Code 로그인)과 `codex` CLI 로그인(ChatGPT 구독)이
되어 있어야 합니다. codex는 구독으로 돌므로 Usage의 codex 비용은 API 환산 추정치.
리서처 상현(X 검색)을 쓰려면 `grok` CLI(Grok Build) 설치 후 `grok login`
(X Premium+/SuperGrok 구독 OAuth)이 필요합니다 — 미설치 시 상현만 실패하고
예림의 웹 조사는 정상 동작합니다. 모든 엔진이 **구독 인증**으로 돌아 API 종량
과금이 없습니다.

```bash
npm -w @agent-loop/orchestrator test   # workspace-guard(보안 경계) + plan-format 테스트
```
